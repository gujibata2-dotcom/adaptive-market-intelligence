# Adaptive Market Intelligence

Research BTC market hypotheses with reproducible, time-ordered validation.
**PROVE BEFORE TRADE — TRUTH BEFORE BELIEF.**

## Interpreting existing evidence

Committed CSVs and the hypothesis ledger are historical results from the old
methodology, **not results regenerated by this update**. Rerun experiments
before relying on their claims. H006/H007 ledger entries currently have no
reproducible experiment scripts in this repository.

Small p-values show association under a model, not profitable trading. The
classifier evaluates predictions made after each daily close, for the next
close. No transaction costs or executable trading strategy are modeled.
A single holdout does not establish robustness across market periods.

## Historical paper account / บัญชีจำลองย้อนหลัง

After analyzing data, set USD starting capital, allocation per entry, buy/sell
probability thresholds, per-side fees/slippage, and a close-only stop-loss.
Click **รันบัญชีจำลอง** for net P&L, return, drawdown, equity history, and trade
CSV exports. The account is long-only, holds one position, and never borrows.
Signals from day t execute at day t+1's close, so no same-close fill is assumed.
When flat, a qualifying signal buys the configured fraction of available cash,
including the buy fee. When held, a sell signal liquidates the entire position.
A close below the stop level sells at that close with adverse slippage; this is
not an intraday stop and cannot guarantee the specified loss limit. The final
position is liquidated with costs; no new entry is allowed on the final day.
Days without signals retain the position subject to the stop. Drawdown includes
open-position mark-to-market, and winning-trade counts include both-side costs.
The buy-and-hold benchmark invests 100% at the first eligible execution close
and exits at the final close with the same friction; it has greater exposure
than the default 25% strategy allocation.

This is a historical simulated account, not a continuously running live paper
broker. It has no broker integration, persistent account, scheduler, exchange
order book, or real-money orders. CSV dates must have daily continuity; model
feature gaps can lead to days without signals. Repeated tuning on the same
holdout overfits that period. Demo-mode profits use synthetic prices only.

## Reliable inputs and multi-period validation

`app/data/btc_sources.py` downloads an entire dataset from one provider; it
never merges Coinbase exchange volume with Yahoo aggregate volume. Requests
use timeouts and bounded HTTP retries. Coinbase pagination stays below the
300-candle limit, filters duplicates/out-of-range/current-day candles, and
requires complete requested daily history. Yahoo fallback also validates daily
continuity. Provider failures do not silently substitute synthetic prices.
Reference: https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles

The dashboard's walk-forward button evaluates three consecutive windows with
an expanding training history and one purged row per boundary. Hyperparameters
and trading settings remain fixed. Window regime labels are descriptive,
assigned after the window ends at ±5% price return, and do not affect signals.
Each window starts a new account. Returns cannot be summed as one continuous
account. This is a first robustness check, not proof of future profitability.

Buy-and-hold now includes a matched-allocation benchmark: invest the same
initial fraction (default 25%) as the strategy and keep the rest in cash.
The 100% benchmark is shown separately. Strategy exposure changes with its
signals and cash balance, so this matches initial allocation, not daily risk.

Reproduce the real Coinbase snapshot results (2021-10-13 through 2026-10-11):

```sh
python experiments/run_paper_validation.py --csv experiments/paper_validation/btc_daily.csv --output /tmp/paper-validation
# Or fetch fresh data:
python experiments/run_paper_validation.py
```

The committed `experiments/paper_validation/` snapshot and outputs were
actually generated with the default settings on Python 3.12. The single
holdout account lost **3.80%**, versus **2.78% loss** for matched buy-and-hold;
maximum strategy drawdown was **13.79%**. Three walk-forward returns were
**-2.64%, +7.63%, -1.50%**. It underperformed matched buy-and-hold in two
windows. This evidence does not justify real-money deployment. These are
historical next-close executions with modeled costs, not live broker fills.

## Feature research / ปรับปรุงตัวแปร

The dashboard now lets you compare **legacy (8)** and **normalized (12)**
feature sets. Legacy remains the default because the new representation did
not improve paper-account performance on the inspected historical snapshot.
The CLI experiment remains legacy-compatible; `run_paper_validation.py`
accepts `--feature-set normalized` for the experimental set.

| Variable | Meaning |
| --- | --- |
| return_1 / return_3 / return_7 | Price percentage change over 1 / 3 / 7 days |
| distance_sma_7 / 20 / 50 | Close divided by rolling mean minus 1; replaces raw price-level SMAs |
| volatility_7 / volatility_20 | Rolling standard deviation of daily returns |
| price_range | (High - Low) / Close |
| close_location | (Close - Low) / (High - Low); 0.5 for zero-range candles |
| volume_log_change | Change in log(1 + Volume); tolerates zero volume |
| volume_relative_20 | Volume divided by the **prior** 20-day mean minus 1 |

All predictors use data available at the current close only. The prediction
label uses the next close and is excluded from model inputs. No ETH, Nasdaq,
DXY or VIX data is invented or forward-filled into this dataset.

Run `python experiments/compare_features.py` to reproduce
`experiments/feature_validation/`. Both sets use identical dates and the same
model/trading settings on the committed real Coinbase snapshot. Summary:

| Metric | Legacy | Normalized experimental |
| --- | --- | --- |
| Holdout accuracy | 48.97% | 50.28% |
| Log loss (lower is better) | 0.7477 | 0.7222 |
| Paper return after costs | -3.80% | -5.59% |
| Maximum drawdown | 13.79% | 12.81% |
| Closed trades | 12 | 28 |

Training-majority accuracy was 50.47%, higher than both models. Walk-forward
results are mixed; no profitability claim or automatic promotion is made.
The historical period has already been inspected, so further comparisons are
exploratory and need confirmation on new unseen data.

`training_permutation.csv` measures model reliance on each experimental
variable inside the **outer training portion** with its own chronological
80/20 split and one purged boundary row. It does not use the final holdout to
select or delete features. A positive log-loss increase means shuffling that
variable hurt this fitted model. Mean/std across ten shuffles are diagnostics,
not p-values or proof of statistical significance; correlated features and
serial dependence affect interpretation. No variables are automatically
removed from these diagnostics. The strongest observed diagnostics were
20-day mean distance, close location, and 50-day mean distance.
